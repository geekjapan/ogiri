### Q1. MVP の既定モデル構成（回答席数 N と各席のプロバイダ/モデル、審査の別系統モデル）
- **対象**: proposal.md「複数プロバイダ混在」/ specs/seat-persona-model / specs/blind-judging（審査の別系統化）
- **なぜ重要**: 回答席が何席で、各席をどのプロバイダ/モデルが駆動し、審査をどのモデルにするかが決まらないと、既定設定・必要 API キー・コスト・TUI レイアウトが定まらない。ブラインド審査は「審査モデルが回答席のどのモデルとも別系統」が成立する必要があり、最低 2 プロバイダ＋審査用にもう 1 系統が要る。
- **検討した選択肢**: A) 回答 3 席（Claude / GPT / Gemini）＋審査は第4系統（例: 別の Gemini or 別ベンダ） / B) 回答 2 席＋審査 1 系統（最小・キー 2 社でも可） / C) 回答 4〜5 席（笑点の人数感だが要キー多数・高コスト）
- **推奨案**: A。笑点の「複数回答者」感と研究のモデル比較を両立しつつ、ブラインド別系統が確実に成立。ただしユーザーの保有キー次第で B に縮退可（キー未設定席は自動スキップする設計なので安全）。
- **不足インプット**: ユーザーが実際に使える/課金してよいプロバイダ（Anthropic / OpenAI / Google など）と、回答席を何席にしたいか。
- **Status**: Resolved — 回答 3 席（Claude/GPT/Gemini）＋審査は別系統の第 4 モデル。キー未設定社は自動スキップで縮退可（proposal.md / design.md D8 / specs/seat-persona-model / tasks.md 3.6 に反映）

### Q2. 司会・山田くんの「語り（中継ナレーション）」を LLM 生成にするか、テンプレート整形にするか
- **対象**: proposal.md「司会／回答者×N／審査の各役割を LLM で埋める」/ specs/tui-broadcast「中継台本風に表示」
- **なぜ重要**: 司会の進行と山田くんの座布団コールを LLM 生成にするとラウンドごとに追加の LLM 呼び出し（コスト・レイテンシ増）が発生するが番組の味は濃くなる。テンプレート整形なら engine は構造化イベントだけ出し TUI が定型文に流し込む（安価・決定的）。MVP の「司会LLM 席」を実装するか否かが分岐し、コストと実装範囲が変わる。
- **検討した選択肢**: A) MVP はテンプレート整形（司会/山田は独立 LLM 席にしない。engine は構造化イベントのみ発行、語りは TUI 側の定型文） / B) 司会も LLM 席にして毎ラウンド語りを生成
- **推奨案**: A。MVP は「動いて観戦できる」を優先し、LLM 呼び出しを回答＋審査に絞ってコストと複雑度を抑える。司会 LLM 化は後続拡張として席抽象に乗せる。
- **不足インプット**: ユーザーが MVP 時点で司会/山田の語りまで LLM の即興に求めるか、定型演出で十分か。
- **Status**: Resolved — テンプレート整形（A）。司会/山田は LLM 席にせず engine の構造化イベントを TUI が定型文化。司会 LLM 化は後続拡張（proposal.md / design.md D8 / specs/seat-persona-model / tasks.md 7.1 に反映）

### Q3. 初期ペルソナを「抽象芸風」にするか、笑点メンバー風味まで寄せるか
- **対象**: design.md D7 / specs/seat-persona-model「初期ペルソナセット（抽象芸風 4〜5 体）」
- **なぜ重要**: 本企画の前提が「笑点」なので、抽象芸風（毒舌/天然/バカ担当/インテリ/シュール）で安全側に倒すか、笑点メンバーの芸風に寄せた味付け（実名は使わずキャラ性だけ寄せる）にするかで体験の手触りが変わる。実名・実在回答の使用は権利上避ける前提は確定済み。
- **検討した選択肢**: A) 抽象芸風 4 体（実名・実在ネタなし） / B) 笑点メンバー風味に寄せた芸風（実名は使わずオマージュ） / C) 抽象芸風だが名前だけ親しみやすい架空名を付与
- **推奨案**: A（または C）。権利安全で、研究の「芸風効果」測定にも素直。笑点らしさは口調・得意技の作り込みで十分出せる。
- **不足インプット**: ユーザーが笑点メンバーへのオマージュ度をどこまで求めるか（安全重視の抽象で良いか）。
- **Status**: Resolved — 笑点メンバー風味に寄せる（B）。実名・実在回答は使わず、口調・得意技・自虐/毒/天然などのキャラ性をオマージュ。few-shot はオリジナル/合成のみ（design.md D7 / specs/seat-persona-model / tasks.md 3.2 に反映）

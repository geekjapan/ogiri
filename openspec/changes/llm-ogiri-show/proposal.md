## Why

複数の LLM に笑点風の大喜利（お題に対する回答）を演じさせ、その様子を観戦したり人間がお題を投げて参加したりできる体験はまだ手軽に存在しない。同時に、生成されたやり取りを構造化ログとして残せば「どのモデル・芸風が日本語の大喜利でウケるか」を数値化・比較する研究ハーネスにもなる。NovelGenSuite はグリーンフィールドであり、エンタメと評価の両面を満たす最初の runnable baseline を小さく立ち上げる好機である。

## What Changes

- TypeScript + Ink による TUI アプリの最初の動作する骨格を新設する（engine を UI から分離し、将来の Web 化とヘッドレス研究実行に備える）。
- 中核抽象として **Seat（席）** を導入する。MVP で LLM が埋めるのは**回答者×N と審査**の席で、**Persona（芸風）と Model（駆動 LLM）は直交**させ、`Seat = Persona × Model` のバインディングとする。司会の進行と山田くんの座布団コール（中継ナレーション）は LLM 席にせず、engine が発行する構造化イベントを TUI 側で定型文に整形して出す（追加の LLM 呼び出しを増やさない。司会 LLM 化は後続拡張）。
- 大喜利の 1 ラウンドを状態機械として実装する: お題提示 → 回答収集（並列）→ ブラインド審査 → 座布団台帳更新 → 中継表示 → 次／終了。お題は独立し、席をまたぐ掛け合いは MVP 対象外とする。
- **複数プロバイダ混在**の LLM アクセスを統一アダプタで提供する（Claude/GPT/Gemini 等。回答席ごとに別モデルを割当可能）。MVP の既定構成は回答 3 席（Claude / GPT / Gemini）＋審査は回答席のいずれとも別系統の第 4 モデルとし、API キー未設定のプロバイダの席は自動スキップする。
- **ブラインド審査**を採用する。審査時に回答者の名前／芸風を隠し、審査モデルは回答モデルと別系統にして自己選好バイアスを避ける。ショー用の即興裁定と研究用の数値化の両立を狙う。
- すべての実行を **構造化トランスクリプト（`transcript.json`）** として出力し、生成と採点を分離する。後から別モデルでの再採点・人間スコアとの相関・リプレイを可能にする。
- 人間参加は MVP では **「お題側」のみ**（自由入力／同梱お題リスト選択／お任せ）。回答席・審査席への人間参戦は将来拡張とし、席抽象に後追いで乗せられる設計にする。
- 非機能: provider ごとの API キーを `.env` で管理し、キーが無い社の席はスキップ。回答は並列収集してレイテンシ差を吸収。片肺故障時はその席を「パス」扱いにし山田くん役がフォロー。LLM 呼び出し回数を台帳に記録する。

## Capabilities

### New Capabilities

- `ogiri-show-engine`: 大喜利 1 ラウンドの状態機械（お題提示→回答収集→審査→台帳更新→次/終了）、座布団台帳、終了条件。UI 非依存・ヘッドレス実行可能な中核。
- `seat-persona-model`: Seat 抽象、Persona（芸風）テンプレートと Model の直交バインディング、初期ペルソナセット、お題のソース（同梱リスト＋自由入力）。
- `llm-provider-adapters`: 複数プロバイダ（Claude/GPT/Gemini 等）を統一インターフェースで叩くアダプタ層、API キー管理、並列収集、片肺故障時のデグレード（席スキップ/パス）。
- `blind-judging`: ブラインド審査（回答者匿名化）、審査モデルの別系統化、座布団付与/没収のルーブリック、自己選好バイアス回避。
- `transcript-logging`: 構造化トランスクリプト出力、生成と採点の分離、リプレイ・再採点・人間スコア相関のためのスキーマ。
- `tui-broadcast`: Ink TUI による中継表示（お題・各回答・審査結果・座布団台帳）と、人間によるお題投入（自由入力/リスト選択/お任せ）。

### Modified Capabilities

（なし。既存 spec は存在しないグリーンフィールド。）

## Impact

- **新規ソースツリー**: これまでアプリのソースは無い（追跡対象は docs と `.claude/` 等の設定のみ）。本変更で TypeScript プロジェクト（engine / providers / tui のパッケージ分離）を新設する。
- **依存**: Node.js + TypeScript、Ink（TUI）、LLM 統一アダプタ候補として Vercel AI SDK（`ai` パッケージ）と各プロバイダ用 provider。
- **設定/秘匿情報**: `.env` による各プロバイダの API キー（コミット禁止）。キー未設定プロバイダはグレースフルにスキップ。
- **ドキュメント**: 最初の runnable baseline 確立に伴い、canonical な setup / lint / test / run コマンドを `CLAUDE.md` と `AGENTS.md` に記録する必要がある。
- **出力成果物**: 実行ごとに `transcript.json`（研究データセットとして再利用可能）。

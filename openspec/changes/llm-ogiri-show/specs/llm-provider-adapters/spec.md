## ADDED Requirements

### Requirement: 統一プロバイダインターフェース
システム SHALL 複数の LLM プロバイダ（Claude/GPT/Gemini 等）を単一のインターフェースで呼び出せるアダプタ層を提供しなければならない（MUST）。engine と席は、どのプロバイダを使うかに依存しないコードで回答・審査を要求できなければならない（MUST）。

#### Scenario: 異なるプロバイダを同一 IF で呼ぶ
- **WHEN** engine が席ごとに別プロバイダのモデルへ回答を要求する
- **THEN** アダプタ層は各プロバイダ固有 API の差異を吸収し、共通の回答結果を返す

#### Scenario: モデル名で駆動先を指定する
- **WHEN** 席にモデル識別子を割り当てて呼び出す
- **THEN** アダプタ層は対応するプロバイダへルーティングして応答を取得する

### Requirement: API キー管理と未設定プロバイダのスキップ
システム SHALL プロバイダごとの API キーを `.env` から読み込み、キーやコードへの秘匿情報の埋め込みを行ってはならない（MUST NOT）。キーが未設定のプロバイダに割り当てられた席は、エラーで停止させずスキップしなければならない（MUST）。

#### Scenario: 未設定プロバイダの席をスキップする
- **WHEN** ある席に割り当てたプロバイダの API キーが `.env` に存在しない
- **THEN** システムはその席を除外（スキップ）し、利用可能なプロバイダの席だけで番組を構成する

#### Scenario: 秘匿情報を出力に含めない
- **WHEN** トランスクリプトやログを出力する
- **THEN** 出力に API キーなどの秘匿情報は一切含まれない

### Requirement: 呼び出し失敗時のデグレード
アダプタ層 SHALL LLM 呼び出しのエラー・タイムアウト・レート制限を捕捉し、呼び出し元の engine が席単位でデグレード（パス）処理できるよう結果に成否を示さなければならない（MUST）。

#### Scenario: タイムアウトを成否として返す
- **WHEN** あるプロバイダ呼び出しが規定時間内に応答しない
- **THEN** アダプタ層は例外を伝播させず、失敗を示す結果を返し engine がパス処理できるようにする

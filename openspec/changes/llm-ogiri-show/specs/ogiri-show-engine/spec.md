## ADDED Requirements

### Requirement: ラウンド進行の状態機械
engine SHALL 大喜利の 1 ラウンドを `お題提示 → 回答収集 → 審査 → 台帳更新 → 次/終了` の状態機械として進行させ、UI に依存せずヘッドレスで実行できなければならない（MUST）。

#### Scenario: 1 ラウンドが順に進行する
- **WHEN** お題が 1 件供給された状態でラウンドを開始する
- **THEN** engine は回答収集→審査→台帳更新の順に状態遷移し、各状態の結果を観測可能なイベントとして発行する

#### Scenario: UI なしのヘッドレス実行
- **WHEN** TUI を起動せず engine を直接呼び出して番組を実行する
- **THEN** engine は LLM 呼び出しと状態遷移を完了し、トランスクリプトと最終台帳を返す

### Requirement: 回答の並列収集とデグレード
engine SHALL 各回答席への LLM 呼び出しを並列に発行し、レイテンシ差を吸収しなければならない（MUST）。いずれかの席が失敗した場合、その席を「パス」として扱い、番組全体は停止してはならない（MUST NOT）。

#### Scenario: 回答を並列収集する
- **WHEN** 複数の回答席が存在する状態で回答収集状態に入る
- **THEN** engine は各席への呼び出しを並列に発行し、全席の結果が出揃ってから（またはタイムアウト後に）審査状態へ進む

#### Scenario: 一部の席が失敗してもショーが続く
- **WHEN** ある回答席の LLM 呼び出しがエラーまたはタイムアウトする
- **THEN** engine はその席を「パス」と記録し、残りの回答で審査と台帳更新を継続する

### Requirement: 座布団台帳の管理
engine SHALL 各席の座布団枚数を台帳として保持し、審査の裁定（付与/没収）を反映しなければならない（MUST）。座布団枚数は 0 を下回ってはならない（MUST NOT）。

#### Scenario: 座布団の付与
- **WHEN** 審査が席に対して座布団 +1 を裁定する
- **THEN** engine はその席の枚数を 1 増やし、履歴に裁定理由とともに記録する

#### Scenario: 座布団の没収は 0 で止まる
- **WHEN** 座布団 0 枚の席に対して没収（-1）が裁定される
- **THEN** engine は枚数を 0 のまま維持し、負数にはしない

### Requirement: 番組終了条件
engine SHALL 設定された終了条件（座布団 N 枚到達、または M ラウンド消化）に達したとき番組を終了し、結果を確定しなければならない（MUST）。

#### Scenario: 規定ラウンド数で終了する
- **WHEN** 設定された M ラウンドを消化する
- **THEN** engine は番組を終了し、各席の最終座布団枚数を含む結果を返す

#### Scenario: 賞品到達で終了する
- **WHEN** いずれかの席が設定された N 枚に到達する
- **THEN** engine は番組を終了し、その席を勝者（賞品獲得）として結果に記録する
